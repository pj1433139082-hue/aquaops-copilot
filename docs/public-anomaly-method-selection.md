# 公开历史异常筛查：方法选择与落地边界

## 目标与边界

本能力只对已登记、已校验哈希的公开历史 WWTP 数据做单指标筛查；它不是实时监测、预测模型或自动控制系统。
每次结果都要求人工复核，不能直接触发加药、曝气、阀门、泵或报警联动。私有水厂、SCADA 和生产数据不进入此模块。

输入固定为一个已支持指标、一个 UTC 截止时间和 1–168 小时基线。基线严格为
`[end_at - baseline_hours, end_at)`，目标观测必须恰好位于 `end_at`。这样目标值不会进入自身的参考分布，避免数据泄漏。

输出是最小化的解释摘要：来源版本、指标与单位、时间边界、基线观测数 `history_count` 与空值数
`history_null_count`、中心位置、已标准化的尺度、稳健分数、方法、方向和 `outcome`。
它刻意不返回目标原始值、原始行、完整数组、CSV 路径或任何私有信息。

尺度字段固定为 `baseline_scale`。可计算时，`method` 为 `rolling_median_mad` 或
`rolling_median_iqr_fallback`；不可筛查时，`method` 必须与原因同名，即 `target_unavailable`、
`insufficient_history` 或 `insufficient_variability`。`outcome` 仅可为 `anomaly`、`normal`、
`target_unavailable`、`insufficient_history` 或 `insufficient_variability`，避免用笼统的 `ok` 掩盖筛查是否实际完成。
`direction` 仅可为 `above_baseline`、`below_baseline` 或 `unavailable`：可计算结果按目标与中位数的符号给出上下方向；两者相等或不可筛查时为 `unavailable`。

## 主方法：滚动 Median + MAD

对有效基线值计算：

```text
m = median(history)
MAD = median(|x - m|)
baseline_scale = 1.4826 × MAD
robust_score = (target - m) / baseline_scale
```

当 `abs(robust_score) >= 3.5` 时，结果标记为异常候选；方向以高于或低于基线中位数表示。
实现选择 Median/MAD 的原因是公开水务时间序列常有尖峰、缺失和短时工况切换。少数极端值会显著拉动均值和标准差，而中位数与 MAD 对这类污染更稳定，且可直接用“相对本窗口中心和离散度偏离了多少”向面试官和业务人员解释。

### MAD 为零时的 IQR 回退

若 MAD 为零，模块按线性分位数计算 `IQR = Q3 - Q1`，并用 `IQR / 1.349` 作为尺度继续计算同一形式的稳健分数。
若 IQR 也为零，则基线没有足够变异度，返回 `insufficient_variability`，而不是凭零除、任意小常数或虚构分数下结论。

这两个尺度在近似正态的参考分布下都转换到可比的标准差量级，因此同一个 `3.5` 阈值有一致的解释。IQR 是回退机制而不是主方法：在小窗口中，IQR 的分位数估计更粗，解释性也不如“典型绝对偏差”直接。`3.5` 是公开演示的保守初始阈值，不应被宣传为任意水厂的生产阈值；部署前必须基于站点、指标和采样频率校准。

## API 端到端边界

仅 operations 模式、且完整匹配下列格式的请求才能进入异常筛查：

```text
公开异常筛查 <指标> <小时数>h 截止 <YYYY-MM-DDTHH:MM:SSZ>
```

API 通过 `POST /v1/agent/runs` 返回受限的 `answer`、唯一的公开来源 `evidence` 与
`requires_human_review=true`。图执行会重新校验严格 schema 和确定性渲染结果；来源、版本、时间边界、
方法和状态只要不一致，或返回中混入原始值、原始行、数组、CSV 路径等未允许字段，均会回落到安全拒答。
正常、异常候选和“证据不足”均不改变非实时、不可自动控制、人工复核的边界。

## 没有采用的方法及原因

| 方法 | 本阶段不作为主方法的原因 | 适合何时再考虑 |
| --- | --- | --- |
| Mean + Std | 对短窗口内尖峰、离群读数敏感；异常本身会抬高均值和标准差，削弱可解释性。 | 数据稳定、已完成异常清洗且近似正态时，可作为对照基线。 |
| IQR-only | 可解释但在短基线与重复值上分位数分辨率有限。 | 作为 MAD 为零时的确定性回退，或业务规则要求分位数边界时。 |
| Isolation Forest | 需要更多历史样本和特征治理；单变量短窗口的训练、漂移、版本与阈值解释成本高。 | 有足够多指标、稳定标签/复核记录和模型监控能力时，作为离线候选方案。 |

## 工程落地约束

- **数据可信边界**：只调用共享的受控公开历史读取器；读取前验证固定来源、路径布局和登记 SHA-256，筛查模块不接受 CSV 路径。
- **精确时间语义**：所有调用时间必须是规范 UTC `Z` 格式。找不到精确目标点（含目标空值）返回 `outcome=target_unavailable`；不使用最近邻插值替代目标。
- **冷启动与缺失**：默认至少需要 48 个有效基线点；不足时返回 `outcome=insufficient_history`，不生成伪异常结论。`history_count` 包含基线内全部观测，`history_null_count` 单独呈现缺失量，空值不参与统计。
- **重复与质量问题**：目标时间存在零个或多个有效点时均不做选择性挑选，统一返回目标不可用；非有限统计量被拒绝。零变异基线返回 `outcome=insufficient_variability`。
- **漂移与季节性**：滚动窗口只刻画短期局部基线，无法独立处理昼夜、降雨、季节或工艺切换。后续若纳入这些因素，需要以经过许可和脱敏的数据建立分层基线，并保留版本化评估。
- **人工闭环**：异常候选应关联到人工复核结论、传感器维护记录和工艺事件；只有在确认数据质量与业务影响后，才进入告警策略讨论。

## 评估与迭代方案

先用公开数据构造可复现回放：按时间滚动产生候选点，记录方法、阈值、状态和人工标注（若有）。重点观察：

- 可用率：`target_unavailable`、`insufficient_history`、`insufficient_variability` 的占比；
- 告警质量：人工复核后的精确率、漏检案例和误报原因；
- 稳定性：不同窗口长度、采样密度和缺失率下的候选率；
- 漂移：按月份、季节、工况分组比较基线中心/尺度与候选率；
- 工程质量：数据哈希校验失败率、端到端延迟和结果 schema 合规率。

达到这些证据前，结果只能表述为“公开历史中的异常候选”，不能表述为在线告警效果、故障诊断结论或自动控制能力。
